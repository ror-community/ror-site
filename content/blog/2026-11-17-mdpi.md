For MDPI, choosing ROR was a natural fit. As an open-access publisher, we are committed to open, transparent, high-quality, and community-driven metadata wherever possible. ROR’s mission aligns closely with these principles: it provides an open and sustainable way to identify research organisations through persistent identifiers.

ROR also offers a standardised and interoperable approach to organisation identification. By using ROR IDs in our affiliation workflows, we can make article metadata more consistent and reusable, while supporting interoperability with services such as [Crossref](https://crossref.org) and other scholarly infrastructure.

At the same time, we chose not to rely directly on the ROR API for affiliation matching. ROR is continuously evolving, with regular updates that include corrections and newly added organisations. For a production system processing affiliation data at scale, keeping organisational data current is essential. Our solution was designed to make it straightforward to incorporate the latest ROR data without substantial manual intervention.

**Ultimately, ROR provides the foundation to turn inconsistent affiliation strings into structured organisational data that supports better research integrity, analytics, discovery, and workflow automation.**

## Using ROR to improve affiliation data and workflows

MDPI’s ROR Entity Search API uses ROR IDs as persistent identifiers to disambiguate free-text affiliation strings. In practice, it takes the unstructured and often inconsistent way institutions are written in research affiliations and maps them to standardised ROR records.

{{< figure src="/img/blog/mdpi/mdpi-ror-entity-search.png" alt="Finding the ROR ID for a long affiliation string." caption="The MDPI ROR Entity Search matches affiliation strings to ROR IDs.">}}

This is particularly valuable because the same organisation can appear in many different forms, languages, abbreviations, or levels of detail. By connecting these variations to a common ROR ID, we can reduce ambiguity and make affiliation data more useful for analytics, reporting, and organisation-aware workflows.

Our API has been used by several internal teams at MDPI for more than a year. For example, it is integrated into our in-house submission system, [SuSy](https://susy.mdpi.com/), where it provides real-time affiliation suggestions as authors enter their affiliations. 

{{< figure src="/img/blog/mdpi/mdpi-susy-affiliations.png" alt="Finding an organization for an author affiliation." caption="MDPI's submission system uses the ROR Entity Search to suggest author affiliations.">}}

This helps standardise institution names at the point of submission and, over time, improves the consistency and interoperability of article metadata. Affiliation disambiguation also supports research-integrity workflows by helping MDPI validate and link authors stated affiliations to recognised institutions, in line with our commitment to maintaining high standards of research integrity.

Furthermore, the API is also used by [Scilit](https://www.scilit.com/), MDPI’s scholarly content aggregation platform, to support affiliation disambiguation at scale. Standardised institutional data enables more reliable institution pages, dashboards, reporting, and organisation-aware analysis across MDPI. For example, the [Institutional Open Access Partnerships (IOAP) program](https://www.mdpi.com/ioap) can use more consistent institutional data to better quantify research output and support data-driven analysis for our IOAP members.

## Integrating ROR at scale

One of the key challenges was not simply matching an affiliation to ROR but doing so reliably across very different workflows and while keeping pace with changes to the ROR dataset.

To address this, we developed the ROR Entity Search API around a modular, two-layer architecture. The first layer provides an easily adaptable representation of the ROR data, while the second handles the search and interpretation of affiliation strings. Keeping these components separate means that we can refresh the underlying ROR data frequently without having to change the search logic each time.

The search process combines several technologies, including named entity recognition to identify institution entities, dense embeddings to capture their semantic meaning, and vector search to retrieve the most likely ROR matches. This approach helps the system handle the noisy, incomplete, and multilingual nature of real-world affiliation data while remaining resilient to variations in how organisations are described. We also designed the API to support different integration scenarios. One search mode returns all ROR IDs identified within an affiliation string, making it suitable for database population and batch processing. A second, top-k suggestion mode returns the most similar ROR IDs, which is better suited to interactive, user-facing applications such as affiliation suggestions during submission.

This API-based approach allows different MDPI teams to use the same underlying affiliation disambiguation capabilities while integrating them into their own workflows.

## What we've learned and what’s next

One of the main lessons we've learned from implementing ROR at scale is that organisation identification is both a metadata challenge and a workflow challenge. Persistent identifiers provide a foundation, but their practical value depends on reliably linking them to the inconsistent affiliation strings found in real-world research metadata.

For us, simplicity and maintainability have been particularly important. ROR is updated regularly, so an effective solution has to keep pace with those changes. Separating the ROR data layer from the search layer has allowed us to do this while keeping the system adaptable. The benefits also extend beyond affiliation matching. **By increasing the use of ROR metadata in MDPI article records deposited with Crossref, we can improve interoperability between publishers, platforms, funders, and indexing organisations.**

We are also making the ROR Entity Search API available externally as both a [freemium API](https://ror.mdpi.com/) and [open-source software](https://github.com/MDPI-AG/ror-search). This means that researchers, publishers, libraries, and other organisations can use the same approach in their own workflows, whether they need a straightforward API integration or want to customise and deploy the open-source solution themselves.

Our aim is ultimately to make organisation identification more accessible and scalable, not only within MDPI, but across the wider scholarly communication ecosystem.
